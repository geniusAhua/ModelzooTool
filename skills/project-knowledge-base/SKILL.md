# 项目知识库（Project Knowledge Base）

把"每次接手一个项目都从零翻代码"变成"先读一页地图，再精准查代码"。
本技能的核心产物是一个**本地、不提交**的知识库文档：它既是项目索引，也是经验备忘。

## 何时触发

> **强制规则（对每一个项目生效）：每一个项目、每一次会话都要执行本流程**——与任务大小无关，与是否“首次接触”无关。把它当成进入项目前的固定动作（step 0），而不是可选建议。

- 只要用户给出项目路径 / 仓库，或你需要在该项目里做分析、接手、跑通、修改、排查、评审等任何事 → **先做本技能**，再动代码 / 命令。
- **项目内不存在** `.project-kb/PROJECT_KNOWLEDGE.md` → 执行第 1 节「初次审阅」，生成一版可用文档。
- **已存在** → 先读文档（第 2 节），再动手；文档与代码不符时以代码为准，并顺手更新。
- 同一会话里换到另一个项目 → 对**新项目**同样重做一遍（不存在“本次会话已经做过”的豁免）。

> 幂等且低成本：文档已存在时，触发本技能只是“先读一页地图”，不会重复生成，所以没有任何理由跳过。

## 知识库位置（固定约定）

| 项 | 值 |
|----|----|
| 目录 | `<项目根>/.project-kb/` |
| 主文档 | `<项目根>/.project-kb/PROJECT_KNOWLEDGE.md` |
| 专题笔记（可选） | `<项目根>/.project-kb/notes/<topic>.md` |
| git 处理 | 把 `.project-kb/` 加入 `.gitignore`（第 4 节） |

固定路径是为了任何一次会话都能**不依赖记忆**找到它。若用户在 `AGENTS.md` 中另行指定，以用户指定为准。

**项目根判定**：优先用用户给定的目录；若它含 `.git/`、`package.json`、`Cargo.toml`、`pyproject.toml`、`go.mod`、`CMakeLists.txt` 等标记，即视为根；否则向上找最近的标记目录；仍找不到就用给定目录。

## 1. 初次审阅（文档不存在时）

目标：用尽量少的成本，产出一份**高信噪比的索引**，不要试图读完整个仓库。

1. **看骨架**：列一层目录，识别源码 / 测试 / 构建脚本 / 文档 / 配置 / 第三方 vendor / 生成物。
2. **读入口与元数据**：README、构建与包管理文件、CI 配置、主入口源文件、示例代码。
3. **抽样理解**：挑 3–5 个核心文件快速通读，搞清"数据与控制怎么流动"。
4. **填模板**：复制 `references/KNOWLEDGE_TEMPLATE.md` 到主文档路径，逐节填写（空节可删）。
5. **配置 gitignore**：见第 4 节。
6. **留白**：把还没搞清、可疑、待确认的点写进「已知问题 / 待确认」，先交付一版可用文档，后续按第 3 节增量补。

### 初次审阅时特别要记录的

「经验与陷阱」是这份文档最有价值的部分，重点记：

- **翻代码代价高、但网络/官方文档/issue 能秒解**的问题 → 记成"别翻代码，直接查 X"。
  例：某个报错在源码里追调用链要很久，但搜索错误关键字第一条就是官方 FAQ。
- **不要在这里搜**：大目录、生成物、vendor/第三方代码，明确标注。
- **有效的检索方式**：该用哪个文件、哪些 grep 关键词、要排除哪些目录。
- **走不通的死胡同**：避免下次重复踩。

## 2. 进入已有知识库的项目（文档存在时）

固定顺序：

1. 先读 `.project-kb/PROJECT_KNOWLEDGE.md`（以及相关的 `notes/`）。
2. 按「目录 / 文件地图」「经验与陷阱」定位，再**精准**查代码。
3. 若文档与代码不符（代码已演进），**以代码为准**，并顺手修正文档。

定位：文档是"索引 + 经验"，不是"真相来源"。关键结论仍要落到代码或命令上验证。

## 3. 增量更新

在下列情况更新文档：

- 发现新的"代码难查、网络易得"的问题；
- 摸清一个之前不清楚的模块；
- 学到一条会反复用到的命令或技巧；
- 发现既有记录有误或已过期。

更新原则：

- 只记**对将来有用、相对稳定**的信息；临时调试过程不要写。
- 每条经验尽量带齐：**现象 / 结论 / 建议动作（去哪查、查什么）**。
- 修改已有条目时保留日期（`YYYY-MM-DD`），便于判断时效。

## 4. gitignore 配置

文档默认不提交，必须保证被忽略：

1. 判断是否 git 仓库：`git rev-parse --show-toplevel`。
   - 报错（非仓库）→ 跳过本步，并在文档中注明"非 git 仓库，未配置忽略"。
2. 确保**仓库根**的 `.gitignore` 含 `.project-kb/`：
   - 没有 `.gitignore` → 创建。
   - 有但缺该条目 → **追加**（保留原有内容，注意结尾换行），可加注释行 `# agent 本地知识库（不提交）`。
   - 已有该条目 → 不动。
3. 若该路径**已被 git 跟踪**（`git ls-files .project-kb` 有输出）→ 需要 `git rm -r --cached .project-kb` 取消跟踪；此操作会改动索引，**先征得用户同意**。

只做上述最小改动，**不要重排或格式化**用户已有的 `.gitignore`。

## 5. 文档模板

见 `references/KNOWLEDGE_TEMPLATE.md`。复制后按实际填写，无内容的节可删除。

## 6. 边界与注意

- **不改动项目源码**来生成文档；只新增 `.project-kb/` 以及对 `.gitignore` 的最小改动。
- **不写机密**（密钥、token、内网口令）；必要时只写"见某处配置"。
- 文档是本地辅助物：不要把它当交付物提交，也不要建议用户提交。
- 保持精简：读文档必须比读代码更快，否则就失去意义。
